# 📧 SKY SEND

**SKY SEND** — веб-сервис на Django для управления email-рассылками. Пользователи могут вести базу клиентов и сообщений, создавать рассылки, запускать их вручную и просматривать историю отправок. Ролевой доступ позволяет разграничивать управление собственными данными и работу менеджеров.

## ✨ Возможности

- Регистрация и авторизация пользователей.
- Управление клиентами: создание, просмотр, редактирование и удаление.
- Управление сообщениями для рассылок.
- Создание и управление рассылками:
  - просмотр списка и подробной информации;
  - создание, редактирование и удаление;
  - ручной запуск;
  - отключение рассылки.
- Просмотр логов отправки.
- Управление пользователями: просмотр списка и блокировка/разблокировка для менеджеров и суперпользователей.
- Разграничение доступа к клиентам, сообщениям и рассылкам.
- Кеширование отдельных списков для повышения производительности.
- Адаптивный интерфейс на Bootstrap 5.

## 🛠 Технологический стек

- Python 3.13
- Django 4.2
- Bootstrap 5
- Poetry
- SQLite (по умолчанию)

## 🚀 Установка и запуск

**Требования**

Установите Python 3.13 и Poetry.

**Подготовка проекта**

```bash
git clone <URL-репозитория>
cd sky_send
poetry install

**Настройка базы данных**

SQLite используется по умолчанию. Если проект настроен на другую базу данных, укажите параметры подключения в конфигурации проекта.

**Миграции и суперпользователь**

```bash
poetry run python manage.py migrate
poetry run python manage.py createsuperuser
```

**Запуск сервера**

```bash
poetry run python manage.py runserver
```

После запуска приложение будет доступно по адресу: <http://127.0.0.1:8000/>.

## 📂 Основные разделы

**Клиенты и сообщения**

| Маршрут | Назначение |
|---|---|
| `/clients/` | Список клиентов |
| `/clients/<id>/` | Карточка клиента |
| `/clients/create/` | Создание клиента |
| `/messages/` | Список сообщений |
| `/messages/<id>/` | Просмотр сообщения |
| `/messages/create/` | Создание сообщения |

**Рассылки**

| Маршрут | Назначение |
|---|---|
| `/mailings/` | Список рассылок |
| `/mailings/<id>/` | Подробная информация о рассылке |
| `/mailings/create/` | Создание рассылки |
| `/mailings/<id>/edit/` | Редактирование рассылки |
| `/mailings/<id>/delete/` | Удаление рассылки |
| `/mailings/<id>/send-now/` | Ручной запуск рассылки |
| `/mailings/<id>/disable/` | Отключение рассылки |

**Пользователи**

| Маршрут | Назначение |
|---|---|
| `/users/login/` | Вход |
| `/users/logout/` | Выход |
| `/users/register/` | Регистрация |
| `/users/list/` | Список пользователей для менеджеров и суперпользователей |
| `/users/block/<id>/` | Блокировка или разблокировка пользователя |

## 🔐 Роли и права доступа

**Суперпользователь**

- Имеет полный доступ к разделам сервиса.
- Видит клиентов, сообщения и рассылки всех пользователей.
- Может просматривать список пользователей и блокировать их.
- Имеет доступ к административной части Django.

**Менеджер**

Пользователь, добавленный в группу `manager`.

- Может просматривать и управлять клиентами, сообщениями и рассылками пользователей.
- Может просматривать список пользователей и блокировать или разблокировать их.
- Не получает доступ к административной части Django только в силу принадлежности к группе.

**Обычный пользователь**

- Работает со своими клиентами, сообщениями и рассылками.
- Не может просматривать список пользователей.
- Не управляет рассылками и данными других пользователей.

## ⚡ Кеширование

Для повышения производительности отдельные списки кешируются с помощью `cache_page`.

Страницы с пользовательским контекстом — например, отображающие текущего пользователя, состояние входа или доступные ему права, — не следует кешировать без дополнительной настройки. Иначе пользователь может увидеть устаревшие или относящиеся к другому пользователю данные.

## 📋 Структура работы с рассылками

1. Создайте клиента или список получателей.
2. Подготовьте сообщение.
3. Создайте рассылку и выберите необходимые данные.
4. Запустите рассылку вручную или отключите её.
5. Проверьте результат в логах отправки.
